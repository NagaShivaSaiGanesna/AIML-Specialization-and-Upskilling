# K-Nearest Neighbors (KNN): A Complete Study Guide

---

## 1. What is K-Nearest Neighbors?

**K-Nearest Neighbors (KNN)** is one of the simplest and most intuitive supervised machine learning algorithms. It works on a beautifully straightforward idea: *a data point is likely to belong to the same class (or have a similar value) as the points closest to it.*

KNN is a **non-parametric, lazy learning** algorithm. "Non-parametric" means it makes no assumptions about the underlying data distribution. "Lazy learning" means it does not build an explicit model during training — it simply memorizes the entire training dataset. All the computation happens at **prediction time**.

KNN can solve **both**:
- **Classification** problems (predicting a category/label)
- **Regression** problems (predicting a continuous value)

---

## 2. The Core Idea: Intuition First

Imagine you move to a new neighborhood and want to predict what kind of food a new restaurant is. You look at the 5 nearest restaurants around it. If 3 of them are Italian and 2 are Mexican, you'd guess the new one is probably Italian. That's KNN — **majority vote among the nearest neighbors**.

For regression, instead of voting, you average the values of your neighbors. If the 5 nearest houses sold for ₹50L, ₹55L, ₹48L, ₹52L, and ₹60L, your best estimate for the new house is their average.

## 3. KNN for Classification

### 3.1 Step-by-Step Algorithm

**Step 1 — Choose the value of K**

$k$ is a **hyperparameter** — a value you set before training, not one the model learns. It represents the number of nearest neighbors to consult.

$$k \in \{1, 2, 3, 4, \ldots, n\}$$

You select the best $k$ through **hyperparameter tuning** (e.g., cross-validation) — try different values and pick the one that maximizes accuracy on a validation set.

**Step 2 — Compute distances from the test point to all training points**

For a new test point, calculate its distance to every point in the training set using a distance metric (covered in Section 4).

**Step 3 — Select the K nearest neighbors**

Sort all training points by distance (ascending) and pick the top $k$ closest ones.

**Step 4 — Take a majority vote**

Count how many of the $k$ neighbors belong to each class. The class with the **highest count wins**.

$$\hat{y} = \arg\max_{c} \sum_{i=1}^{k} \mathbb{1}[y_i = c]$$

Where $\mathbb{1}[\cdot]$ is the indicator function (1 if true, 0 if false) and $c$ is a class label.

### 3.2 Worked Example

Suppose $k = 5$ and your test point's 5 nearest neighbors have labels: `[1, 0, 1, 1, 0]`

- Count of class `0`: **2**
- Count of class `1`: **3**

$$\hat{y} = 1 \quad \text{(majority vote)}$$

The test point is classified as **class 1**.

## 4. Distance Metrics

To find "nearest" neighbors, you need a way to measure distance. The two most common metrics are Euclidean and Manhattan distance.

### 4.1 Euclidean Distance

This is the **straight-line distance** between two points — the shortest path through space (as the crow flies).

For two points $\mathbf{p} = (x_1, y_1)$ and $\mathbf{q} = (x_2, y_2)$ in 2D:

$$d_{\text{Euclidean}}(\mathbf{p}, \mathbf{q}) = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}$$

Generalized to $n$ dimensions:

$$d_{\text{Euclidean}}(\mathbf{p}, \mathbf{q}) = \sqrt{\sum_{i=1}^{n} (q_i - p_i)^2}$$

**Real-world analogy:** The distance a flight travels from Mumbai to Delhi — a straight path through the air, ignoring roads.

### 4.2 Manhattan Distance

This is the **grid-based distance** — total horizontal plus vertical displacement, like navigating city blocks. You cannot cut diagonally through buildings.

For two points $\mathbf{p} = (x_1, y_1)$ and $\mathbf{q} = (x_2, y_2)$:

$$d_{\text{Manhattan}}(\mathbf{p}, \mathbf{q}) = |x_2 - x_1| + |y_2 - y_1|$$

Generalized to $n$ dimensions:

$$d_{\text{Manhattan}}(\mathbf{p}, \mathbf{q}) = \sum_{i=1}^{n} |q_i - p_i|$$

**Real-world analogy:** The route an Uber takes from one block to another in a grid-planned city — it must follow roads, not cut through buildings.

### 4.3 Comparison Table

| Property | Euclidean Distance | Manhattan Distance |
|---|---|---|
| **Path type** | Straight line (diagonal allowed) | Axis-aligned steps only |
| **Formula** | $\sqrt{\sum (q_i - p_i)^2}$ | $\sum \|q_i - p_i\|$ |
| **Sensitive to outliers** | More (squares differences) | Less (linear differences) |
| **Best used when** | Features are continuous, space is open | Grid-like data, or features with different scales |
| **Real-world use case** | Air travel, GPS shortest path | City navigation, taxi routing |

> **Which to use?** In practice, try both and pick whichever gives better cross-validation accuracy. Euclidean is the default choice for most continuous-feature datasets.

## 5. KNN for Regression

All steps are identical to classification, with **one key difference at the final step**: instead of a majority vote, you compute the **mean** (or **median**) of the $k$ neighbors' output values.

$$\hat{y} = \frac{1}{k} \sum_{i=1}^{k} y_i$$

**When to use median instead of mean:** If your dataset contains **outliers**, the median is more robust since extreme values cannot skew it.

### 5.1 Example

Predicting house price for a new data point. The 5 nearest neighbors have prices (in lakhs): `[48, 50, 52, 55, 60]`

$$\hat{y} = \frac{48 + 50 + 52 + 55 + 60}{5} = \frac{265}{5} = 53 \text{ lakhs}$$

## 6. Choosing K: The Bias-Variance Tradeoff

The value of $k$ directly controls the **bias-variance tradeoff** of the model:

| $k$ value | Bias | Variance | Behavior |
|---|---|---|---|
| **Very small** (e.g., $k=1$) | Low | High | Overfits — too sensitive to noise and individual points |
| **Very large** (e.g., $k=n$) | High | Low | Underfits — decision boundary becomes too smooth, ignores local patterns |
| **Optimal** (via CV) | Balanced | Balanced | Generalizes well to unseen data |

**Rule of thumb:** A common starting point is $k = \sqrt{n}$, where $n$ is the number of training samples. Always validate with cross-validation.

## 7. Time Complexity and Variants

### 7.1 The Scalability Problem

The naive KNN algorithm has a prediction time complexity of:

$$\mathcal{O}(n \cdot d)$$

where $n$ is the number of training points and $d$ is the number of features (dimensions). For **millions of data points**, this becomes prohibitively slow — you must compute distance to every single training point for every prediction.

### 7.2 Optimized Variants

To address this, tree-based data structures are used to **partition the feature space**, drastically reducing the number of distance calculations required.

| Variant | Structure | How it Helps | Best For |
|---|---|---|---|
| **KD-Tree** | Binary tree partitioning on alternating dimensions | Prunes entire branches; distance to many points computed implicitly | Low-to-moderate dimensions ($d \leq 20$) |
| **Ball Tree** | Hypersphere-based partitions | Handles curved geometry better than KD-Tree | Higher dimensions, non-Euclidean metrics |

Both structures reduce average prediction complexity from $\mathcal{O}(n)$ toward $\mathcal{O}(\log n)$ in favorable cases, making KNN practical at scale.

## 8. Limitations, Assumptions & Pitfalls

### Limitations
- **Computationally expensive at prediction time** — scales poorly with large datasets without optimized structures.
- **High memory usage** — the entire training dataset must be stored in memory.
- **Sensitive to irrelevant features** — noisy or irrelevant features distort distance calculations. Feature selection and scaling are critical.

### Assumptions
- **Feature scales matter**: KNN assumes all features contribute equally to distance. A feature with range `[0, 10000]` will dominate one with range `[0, 1]`. **Always normalize or standardize features** (e.g., Min-Max scaling or Z-score normalization) before applying KNN.
- **Local uniformity**: KNN assumes that the label distribution is locally consistent — nearby points tend to share the same label.

### Common Pitfalls
- **Not scaling features**: This is the #1 mistake. Without scaling, KNN's distances are meaningless.
- **Choosing $k=1$**: Almost always overfits. Never use $k=1$ without strong justification.
- **Choosing an even $k$ for binary classification**: Can lead to ties (e.g., 2 votes each). Prefer **odd values of $k$** for binary problems.
- **Ignoring the curse of dimensionality**: As the number of features grows, all points become approximately equidistant from each other, making "nearest neighbors" meaningless. Dimensionality reduction (PCA, etc.) is recommended for high-dimensional data.

## 9. FAANG-Level Q&A

**Q1. What if all K nearest neighbors are from different classes (a perfect tie in a multi-class setting)?**

Several strategies exist: (1) **reduce $k$ by 1** iteratively until the tie breaks; (2) use **distance-weighted voting**, where closer neighbors get higher weight ($w_i = 1/d_i$), making ties extremely rare; (3) pick the class with the smallest average distance to the test point. In practice, distance-weighted KNN ($\hat{y} = \arg\max_c \sum_{i: y_i=c} \frac{1}{d_i}$) is the most principled tie-breaking approach and often improves accuracy overall.

**Q2. What if the dataset is severely imbalanced (e.g., 95% class 0, 5% class 1)?**

Standard KNN will almost always predict the majority class, since most neighbors will belong to it by chance. Solutions include: (1) **distance-weighted voting** to amplify the influence of very close minority-class neighbors; (2) **oversampling the minority class** (e.g., SMOTE) before training; or (3) using **stratified cross-validation** when tuning $k$, ensuring minority class is always represented in validation folds.

**Q3. What if a feature has missing values — can KNN still compute distances?**

Missing values break standard distance formulas. Common strategies are: (1) **impute before applying KNN** using mean/median/mode, though this distorts distances; (2) use a **modified distance metric** that averages only over observed dimensions, scaling by $\frac{d}{d_{\text{observed}}}$ to penalize high missingness; or (3) use **KNN imputation itself** — find neighbors based on non-missing features, then impute missing values from those neighbors. Option 3 is often the most principled.

**Q4. Design a KNN-based product recommendation system for 100 million users and 10 million products.**

Naive KNN is completely infeasible at this scale. The architecture must use **Approximate Nearest Neighbor (ANN)** search via libraries like **FAISS** (Facebook AI Similarity Search) or **ScaNN** (Google), which use techniques like **Product Quantization** and **HNSW (Hierarchical Navigable Small World) graphs** to retrieve approximate top-$k$ neighbors in $\mathcal{O}(\log n)$ time with sub-linear memory. User and product representations are first compressed into dense embeddings via matrix factorization or neural collaborative filtering, reducing the feature space to ~$d = 128$ before ANN indexing. The index is sharded across machines and rebuilt periodically (e.g., nightly), with a serving layer that retrieves candidates in milliseconds at the 99th percentile. This architecture powers production recommendation systems at Spotify, Pinterest, and Amazon.
