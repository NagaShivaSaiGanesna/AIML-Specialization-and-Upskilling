## 1. Why We Need Specialized Metrics for Classification

In **regression**, we measured model quality with $R^2$ and Adjusted $R^2$ — metrics that quantify how well a continuous predicted value matches the true continuous value.

In **classification**, the output is a discrete category (e.g., spam/not spam, fraud/not fraud). The concept of "how far off" a prediction is does not directly apply — a wrong prediction is simply wrong. We need metrics that count and categorize the *types* of errors a model makes.

The foundation of all classification metrics is the **confusion matrix**.

---

## 2. The Confusion Matrix

A **confusion matrix** is a table that organizes every prediction a model makes into one of four buckets by comparing the **actual (true) label** against the **predicted label**.

### 2.1 Structure (Binary Classification)

For binary classification (classes 1 and 0), the confusion matrix is a $2 \times 2$ table:

|  | **Predicted: 1** | **Predicted: 0** |
|---|---|---|
| **Actual: 1** | True Positive (TP) | False Negative (FN) |
| **Actual: 0** | False Positive (FP) | True Negative (TN) |

### 2.2 Definitions of Each Cell

| Term | Abbreviation | What it means |
|---|---|---|
| **True Positive** | TP | Model predicted 1, and the actual label was 1. **Correct.** |
| **True Negative** | TN | Model predicted 0, and the actual label was 0. **Correct.** |
| **False Positive** | FP | Model predicted 1, but the actual label was 0. **Wrong.** (Type I Error) |
| **False Negative** | FN | Model predicted 0, but the actual label was 1. **Wrong.** (Type II Error) |

**Key intuition:**
- The **diagonal** (TP and TN) represents all **correct** predictions.
- The **off-diagonal** (FP and FN) represents all **incorrect** predictions.

### 2.3 Multi-Class Extension

For a problem with $K$ output classes, the confusion matrix becomes a $K \times K$ matrix. Each row represents the actual class and each column represents the predicted class. The diagonal still represents correct predictions. Per-class precision and recall are computed by treating each class as the "positive" class in a one-vs-all manner.

---

## 3. Accuracy

**Accuracy** is the most intuitive metric: the fraction of all predictions that were correct.

$$\text{Accuracy} = \frac{TP + TN}{TP + FP + FN + TN}$$

### 3.1 Worked Example

Given the following confusion matrix:

|  | **Predicted: 1** | **Predicted: 0** |
|---|---|---|
| **Actual: 1** | TP = 3 | FN = 1 |
| **Actual: 0** | FP = 2 | TN = 1 |

$$\text{Accuracy} = \frac{3 + 1}{3 + 2 + 1 + 1} = \frac{4}{7} \approx 0.571$$

The model correctly classified approximately **57.1%** of all samples.

---

## 4. The Class Imbalance Problem

Accuracy is dangerously misleading when the dataset is **imbalanced** — i.e., when one class vastly outnumbers the other.

### 4.1 Illustrative Example

Suppose you have a dataset of 1,000 patients:
- 900 do **not** have a disease (label = 0)
- 100 **do** have the disease (label = 1)

A completely useless model that always predicts 0 (no disease) achieves:

$$\text{Accuracy} = \frac{0 + 900}{0 + 0 + 100 + 900} = \frac{900}{1000} = 90\%$$

This 90% accuracy is entirely misleading — the model has **zero ability to detect disease**. This is why we need **Precision** and **Recall** for imbalanced problems.

---

## 5. Precision

**Precision** answers the question: *"Of all the samples my model labeled as positive, how many actually were positive?"*

$$\text{Precision} = \frac{TP}{TP + FP}$$

Precision focuses on **minimizing False Positives**. A high precision means: when the model says "positive," you can trust it.

### 5.1 Intuition

Think of precision as the model's **reliability when it raises an alarm**. If the model fires an alarm 100 times and 95 of them are real threats, precision is 0.95 — the model is very trustworthy.

If precision is low, the model cries wolf too often — it raises many false alarms (high FP).

---

## 6. Recall (Sensitivity)

**Recall** answers the question: *"Of all the samples that were actually positive, how many did my model correctly identify?"*

$$\text{Recall} = \frac{TP}{TP + FN}$$

Recall focuses on **minimizing False Negatives**. A high recall means: the model rarely misses a true positive case.

### 6.1 Intuition

Think of recall as the model's **coverage**. If there are 100 real diseases in the population and the model catches 90 of them, recall is 0.90. The 10 it missed are **False Negatives** — dangerous misses.

---

## 7. When to Use Precision vs. Recall

The choice between optimizing precision vs. recall depends entirely on the **cost of each type of error** in your specific domain.

### 7.1 Use Case: Spam Classification — Optimize Precision

| Scenario | Error Type | Consequence |
|---|---|---|
| Spam mail predicted spam | TP | Correct, model working well |
| Legit mail predicted spam | **FP** | **Major blunder** — important email silently lost |
| Spam mail predicted legit | FN | Annoying, but user sees and can delete it |

**Critical error:** False Positive — a legitimate email is incorrectly sent to the spam folder.

**Metric to optimize:** **Precision** — minimize FP. Better to let some spam through than to block legitimate email.

### 7.2 Use Case: Disease Detection — Optimize Recall

| Scenario | Error Type | Consequence |
|---|---|---|
| Has disease, predicted positive | TP | Correct, patient gets treatment |
| No disease, predicted positive | FP | Patient gets a second opinion — manageable |
| Has disease, predicted negative | **FN** | **Major blunder** — sick patient sent home untreated |

**Critical error:** False Negative — a patient who has the disease is told they are healthy.

**Metric to optimize:** **Recall** — minimize FN. Better to over-refer (high FP) than to miss a sick patient.

### 7.3 Summary Decision Guide

| Worst Outcome | Minimize | Metric to Use |
|---|---|---|
| False alarm (FP) is the worst outcome | False Positive | **Precision** |
| Missed detection (FN) is the worst outcome | False Negative | **Recall** |
| Both errors are equally bad | Both FP and FN | **F1 Score** |

---

## 8. F-Beta Score

The **F-Beta score** is a single metric that balances precision and recall. The parameter $\beta$ controls how much weight to give recall relative to precision.

$$F_\beta = (1 + \beta^2) \cdot \frac{\text{Precision} \times \text{Recall}}{\beta^2 \cdot \text{Precision} + \text{Recall}}$$

### 8.1 Special Cases

#### F1 Score ($\beta = 1$): Equal Weight on Precision and Recall

Use when **both FP and FN are equally costly**.

$$F_1 = 2 \cdot \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$$

This is the **harmonic mean** of precision and recall. The harmonic mean is preferred over the arithmetic mean because it penalizes extreme imbalances — a model with precision = 1.0 and recall = 0.0 gets $F_1 = 0$, correctly indicating failure.

#### F0.5 Score ($\beta = 0.5$): Precision More Important

Use when **FP is more costly than FN** (e.g., spam detection).

$$F_{0.5} = (1 + 0.25) \cdot \frac{\text{Precision} \times \text{Recall}}{0.25 \cdot \text{Precision} + \text{Recall}}$$

A $\beta < 1$ weights precision more heavily than recall.

#### F2 Score ($\beta = 2$): Recall More Important

Use when **FN is more costly than FP** (e.g., disease detection, fraud detection).

$$F_2 = (1 + 4) \cdot \frac{\text{Precision} \times \text{Recall}}{4 \cdot \text{Precision} + \text{Recall}} = 5 \cdot \frac{\text{Precision} \times \text{Recall}}{4 \cdot \text{Precision} + \text{Recall}}$$

A $\beta > 1$ weights recall more heavily than precision.

### 8.2 Beta Selection Guide

| Scenario | Beta Value | Score Name | What It Prioritizes |
|---|---|---|---|
| Both errors equally bad | $\beta = 1$ | F1 | Balance |
| FP worse than FN | $\beta < 1$ (e.g., 0.5) | F0.5 | Precision |
| FN worse than FP | $\beta > 1$ (e.g., 2) | F2 | Recall |

---

## 9. Concept Summary Table

| Metric | Formula | Focuses On | When to Use |
|---|---|---|---|
| **Accuracy** | $\frac{TP+TN}{TP+FP+FN+TN}$ | Overall correctness | Balanced datasets only |
| **Precision** | $\frac{TP}{TP+FP}$ | Minimizing false alarms | FP is costly (spam, ad targeting) |
| **Recall** | $\frac{TP}{TP+FN}$ | Minimizing missed detections | FN is costly (disease, fraud) |
| **F1 Score** | $2 \cdot \frac{P \cdot R}{P+R}$ | Balance of P and R | Imbalanced data, both errors matter |
| **F-Beta Score** | $(1+\beta^2)\frac{P \cdot R}{\beta^2 P + R}$ | Tunable P/R tradeoff | Custom cost of FP vs FN |

## 10. Limitations, Assumptions & Pitfalls

### Limitations
- **Accuracy is unreliable on imbalanced data.** A 99% accurate model on a 99:1 dataset may be completely useless, having learned to predict only the majority class. Always check the class distribution before trusting accuracy.
- **Precision and recall are inversely related.** Improving one typically degrades the other. This **precision-recall tradeoff** is fundamental and unavoidable without improving the underlying model.
- **F1 treats FP and FN as equally costly.** In most real-world problems this is not true. Use $F_\beta$ with a thoughtfully chosen $\beta$ rather than defaulting to F1.
- **These metrics say nothing about probability calibration.** A model can have high F1 yet produce poorly calibrated probabilities. Use calibration curves or the Brier score when probability estimates matter.

### Assumptions
- Metrics are computed on a **held-out test set** the model has never seen. Evaluating on training data produces optimistically biased estimates.
- The **decision threshold** (default 0.5) is assumed when computing the confusion matrix. Changing the threshold changes TP, FP, FN, TN and therefore every metric derived from them.

### Pitfalls
- **Macro vs. Micro averaging in multi-class:** "Precision" can mean (a) the average precision across all classes (macro), or (b) the globally aggregated precision across all instances (micro). Macro averaging treats all classes equally; micro averaging is dominated by the most frequent class. Choose deliberately.
- **Reporting only one metric:** Always report at minimum precision, recall, and F1 together. Reporting only accuracy creates a misleadingly incomplete picture on any real dataset.
- **Choosing $\beta$ without domain input:** The value of $\beta$ encodes the relative cost of FN vs. FP. This is a **business/domain decision**, not a technical one. Consult domain experts before fixing $\beta$.

### Q1. *(What If / Edge Case)* What happens to precision and recall when the decision threshold is changed from 0.5 to a very high value like 0.95? What about a very low value like 0.05?

**Answer:**

The classification threshold $t$ determines when a predicted probability $h_\theta(x) \geq t$ is labeled positive (class 1). Changing $t$ does not retrain the model — it reshuffles which examples fall into TP, FP, FN, and TN.

**High threshold ($t = 0.95$):**

The model only predicts "positive" when extremely confident, drastically reducing predicted positives.

- **TP decreases** — many true positives no longer exceed the bar and are predicted negative.
- **FP decreases sharply** — the model rarely fires, so false alarms are rare.
- **FN increases** — many genuine positives are now missed.

Result: **Precision $\uparrow$, Recall $\downarrow$.**

$$\text{Precision} = \frac{TP}{TP + FP} \uparrow \qquad \text{Recall} = \frac{TP}{TP + FN} \downarrow$$

**Low threshold ($t = 0.05$):**

The model predicts "positive" for almost everything.

- **TP and FP both increase** — nearly all positives are caught (high recall) but many negatives are also flagged.
- **FN decreases** — almost no true positive is missed.

Result: **Recall $\uparrow$, Precision $\downarrow$.**

**The full tradeoff — Precision-Recall Curve:**

By sweeping $t$ from 0 to 1 and computing precision and recall at each point, we trace the **Precision-Recall (PR) curve**. The **Area Under the PR Curve (AUC-PR)** summarizes model quality across all thresholds and is superior to AUC-ROC for highly imbalanced datasets because it is not distorted by the large number of true negatives.

| Threshold | Precision | Recall | F1 |
|---|---|---|---|
| Very low (0.05) | Low | High | Moderate |
| Default (0.50) | Moderate | Moderate | Moderate |
| Very high (0.95) | High | Low | Moderate |

The optimal threshold is selected based on domain cost analysis, not arbitrarily set at 0.5.

---

### Q2. *(What If / Edge Case)* A model achieves Precision = 1.0 and Recall = 0.0. What does this mean, and what is its F1 score? Is this model useful?

**Answer:**

**What it means:**

- **Precision = 1.0** means every single prediction of "positive" was correct — zero false positives.
- **Recall = 0.0** means the model never predicted "positive" at all — it predicted "negative" for every single example, producing zero true positives.

This is the extreme case of a model that refuses to make any positive prediction. It avoids all false alarms perfectly but misses every true case entirely.

**F1 Score:**

$$F_1 = 2 \cdot \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}} = 2 \cdot \frac{1.0 \times 0.0}{1.0 + 0.0} = 0$$

The F1 score is **0** — correctly capturing that this model is completely useless despite its "perfect" precision.

**Why the harmonic mean is the right choice here:**

The arithmetic mean of precision and recall would give $\frac{1.0 + 0.0}{2} = 0.5$, suggesting a mediocre but functional model. The harmonic mean:

$$H = \frac{2}{\frac{1}{P} + \frac{1}{R}}$$

approaches zero whenever *either* term approaches zero. This correctly captures the intuition that a model must demonstrate *both* reasonable precision and reasonable recall to be useful — it cannot trade one completely away for the other.

**Practical analogy:** This model is a fire alarm that never triggers — zero false alarms, but also zero fires detected.

### Q3. *(System Design at Scale)* Design a fraud detection system for a payments company processing 50 million transactions per day. Define the metrics strategy, class imbalance handling, and production monitoring approach.

**Answer:**

**Step 1: Establish the Cost Matrix**

Before writing a single line of code, quantify the cost of each error type with the business:

| Error Type | Scenario | Estimated Cost |
|---|---|---|
| False Negative | Fraud approved — money lost | $200–$500 per case (chargeback + fees) |
| False Positive | Legit transaction blocked | $5–$15 (friction, churn risk) |

Since FN is ~20–100× more costly than FP, we optimize **Recall** and use **$F_2$ score** as the primary offline metric.

**Step 2: Handle Class Imbalance**

With a typical fraud rate of ~0.05%, a 50M daily transaction dataset has ~25,000 fraud cases vs. ~49,975,000 legitimate ones.

Strategies:

1. **Cost-sensitive learning:** Set `class_weight = {0: 1, 1: 100}` in sklearn, encoding relative FN/FP cost directly into the training loss.
2. **Threshold tuning:** Train with standard weights, then lower the decision threshold (e.g., $t = 0.15$) on a validation set to maximize $F_2$.
3. **Resampling:** Use SMOTE on the minority class or random undersampling of the majority class during training.

**Step 3: Offline Evaluation Metrics**

| Metric | Purpose |
|---|---|
| $F_2$ Score | Primary — penalizes FN more than FP |
| Precision @ fixed Recall | E.g., precision when recall = 0.90 (business SLA) |
| AUC-PR | Model comparison across all thresholds |
| KS Statistic | Separation between fraud and legit score distributions |

Never report raw accuracy — a model predicting all-legit achieves 99.95% accuracy with zero fraud detection.

**Step 4: Production Monitoring**

- **Rolling metrics dashboard:** Compute 1-hour and 24-hour precision, recall, and $F_2$ from labeled outcomes (labels arrive within 30–90 days via chargebacks).
- **Population Stability Index (PSI):** Monitor input feature distributions daily. PSI > 0.2 on key features triggers model review.
- **Champion-challenger:** Route 5% of traffic to a retrained challenger model. Promote only when $F_2$ and dollar-loss metrics improve.

### Q4. *(System Design at Scale)* You are building a content moderation system for a social platform with 200 million daily posts. How do you choose between precision and recall, and how do you scale evaluation?

**Answer:**

**Precision vs. Recall by Content Type:**

| Content Type | Critical Error | Primary Metric | Reasoning |
|---|---|---|---|
| Child safety material | FN (missed content) | **Recall** | Legal obligation; one miss is catastrophic |
| Graphic violence | FN (missed content) | **Recall** | High harm; lean toward over-removal |
| Spam / low-quality content | FP (wrongful removal) | **Precision** | Over-removal frustrates users |
| Misinformation | Both | **F1 / F2** | False removals create censorship risk; false negatives spread harm |

**Scaling Evaluation at 200M Posts/Day:**

Direct human review of all predictions is infeasible. Use a stratified sampling strategy:

1. **Confidence-stratified sampling:** Sample heavily from uncertain predictions ($0.4 < h_\theta(x) < 0.6$) and lightly from high-confidence predictions. This maximizes information per human review hour.
2. **Per-category metrics:** A single aggregate $F_1$ obscures performance on rare but high-stakes categories. Track separate metrics per content type.
3. **Tiered automation pipeline:** Auto-remove content above $t = 0.95$; auto-approve below $t = 0.10$; route the middle band to human review queues prioritized by severity score.
4. **Inter-annotator agreement:** Track Cohen's Kappa between reviewers on ambiguous cases. Low agreement signals label quality issues, making any downstream metric unreliable.

### Q5. *(Math / Theory Deep-Dive)* Prove that the F1 score is the harmonic mean of precision and recall, and explain mathematically why the harmonic mean is more appropriate than the arithmetic mean for this purpose.

**Answer:**

**Part 1: F1 is the Harmonic Mean**

The harmonic mean of two positive numbers $a$ and $b$ is:

$$H(a, b) = \frac{2}{\frac{1}{a} + \frac{1}{b}} = \frac{2ab}{a + b}$$

Setting $a = \text{Precision}$ and $b = \text{Recall}$:

$$H(P, R) = \frac{2PR}{P + R} = F_1 \quad \blacksquare$$

**Part 2: Why Not the Arithmetic Mean?**

The arithmetic mean $A(P, R) = \frac{P + R}{2}$ is insensitive to extreme imbalances:

| Model | Precision | Recall | Arithmetic Mean | Harmonic Mean (F1) |
|---|---|---|---|---|
| A (balanced) | 0.50 | 0.50 | 0.50 | **0.50** |
| B (never predicts positive) | 1.00 | 0.00 | 0.50 | **0.00** |
| C (barely recalls) | 0.90 | 0.10 | 0.50 | **0.18** |

Models B and C receive the same arithmetic mean as the genuinely balanced Model A. This is clearly wrong.

**Formal property — the harmonic mean is dominated by the minimum:**

For $P, R \in (0, 1]$, assume without loss of generality $P \leq R$. Then:

$$H(P, R) = \frac{2PR}{P + R} \leq \frac{2P \cdot R}{P + P} = \frac{2PR}{2P} = R$$

$$H(P, R) = \frac{2PR}{P + R} \leq \frac{2P \cdot P}{P + P} = \frac{2P^2}{2P} = P$$

Therefore $H(P, R) \leq \min(P, R)$. A very low precision *or* recall pulls F1 toward zero regardless of how high the other value is. A useful model must demonstrate both — the harmonic mean enforces this algebraically.

### Q6. *(Cross-Topic Connection)* How do precision and recall in ML classification relate to Type I and Type II errors in statistical hypothesis testing? Where does this analogy break down?

**Answer:**

**The Direct Mapping**

| Hypothesis Testing | Binary Classification |
|---|---|
| Null hypothesis $H_0$ (e.g., "no effect") | Negative class (label = 0) |
| Alternative hypothesis $H_1$ (e.g., "effect exists") | Positive class (label = 1) |
| **Type I Error** — reject $H_0$ when true | **False Positive** |
| **Type II Error** — fail to reject $H_0$ when $H_1$ is true | **False Negative** |
| Significance level $\alpha$ | $1 - \text{Precision}$ |
| Statistical power $(1 - \beta_{\text{stat}})$ | **Recall** |
| Lowering $\alpha$ (stricter test) | Raising decision threshold $t$ |

The precision-recall tradeoff mirrors the power-$\alpha$ tradeoff: reducing Type I errors (higher $\alpha$ threshold) generally increases Type II errors (lower power), just as higher precision generally reduces recall.

**Where the Analogy Breaks Down:**

1. **Continuous scores vs. binary decisions:** A classifier produces a continuous probability $h_\theta(x)$ that can be thresholded at any $t$, tracing the full PR curve. A hypothesis test typically commits to a single operating point at a fixed $\alpha$.

2. **The base rate problem:** Precision is directly affected by **class prevalence**. In a population where only 1 in 10,000 people has a rare disease, even a highly sensitive test (high recall) will have low precision — this is the **base rate fallacy**. In Bayesian terms:

$$\text{Precision} = P(y=1 \mid \hat{y}=1) = \frac{P(\hat{y}=1 \mid y=1) \cdot P(y=1)}{P(\hat{y}=1)}$$

Recall $= P(\hat{y}=1 \mid y=1)$ does not depend on the prior $P(y=1)$. This means recall is a more stable metric when class prevalence shifts between training and deployment — a very common scenario in production ML.

3. **Multiple comparisons:** Hypothesis testing has rigorous frameworks (Bonferroni correction, False Discovery Rate) for controlling error rates across many simultaneous tests. The classification analog — evaluating across many subgroups or thresholds — is far less standardized and is a known weakness in applied ML evaluation.
