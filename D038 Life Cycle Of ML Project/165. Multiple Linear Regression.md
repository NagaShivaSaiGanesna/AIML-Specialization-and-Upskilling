# Multiple Linear Regression: House Price Prediction Guide

This guide details the implementation of **Multiple Linear Regression** using the California Housing dataset. Unlike simple linear regression, this model handles multiple independent variables simultaneously to predict a target outcome.

---

## 1. Concept: Multiple vs. Simple Regression
The core difference lies in the number of predictors. In multiple regression, we map several features to a single output, resulting in multiple coefficients (slopes).

**The General Equation:**
$$y = \beta_0 + \beta_1 x_1 + \beta_2 x_2 + ... + \beta_n x_n + \epsilon$$

Where:
* $x_1, x_2, ..., x_n$ are different independent features (e.g., House Age, Income, Rooms).
* $\beta_1, \beta_2, ..., \beta_n$ are the respective coefficients for those features.

## 3. The Implementation Pipeline

### Step 1: Feature Splitting & Scaling
Just as in simple regression, we split data into training (67%) and testing (33%) sets. **Standardization** is mandatory because features like `Population` and `HouseAge` exist on different scales.

### Step 2: Model Training
We fit the `LinearRegression` model. After training, the model provides **eight coefficients**—one for each input feature—and **one intercept**.

### Step 3: Evaluation Metrics
We use $R^2$ and **Adjusted $R^2$** to measure accuracy.
* **$R^2$:** Measures how well the model fits the data.
* **Adjusted $R^2$:** More reliable for multiple regression as it only increases if the new variable improves the model more than would be expected by chance.

---

## 4. Model Assumptions & Diagnostics
Because Multiple Linear Regression is a linear model, we must validate these assumptions via **Residual Analysis**:

1.  **Linearity:** The relationship between $y$ and the $x$ variables should be approximately linear.
2.  **Normality of Residuals:** If we plot a distribution of the errors ($y_{test} - y_{pred}$), it should ideally follow a **Bell Curve (Normal Distribution)**.
3.  **Homoscedasticity:** The error variance should be constant. If the residual plot shows a clear pattern (like a funnel shape), the model is likely missing non-linear relationships.

## 5. Model Deployment: Pickling
Once the model is trained, we need to save it for use in production (e.g., a web app or cloud service) without retraining. This is called **Serialization**.

* **Pickling:** Converting a Python object (our model) into a byte stream to save as a `.pkl` file.
* **Unpickling:** Loading that byte stream back into a Python object for predictions.

```python
import pickle
# Saving the model
pickle.dump(regressor, open('model.pkl', 'wb'))

# Loading the model for future use
loaded_model = pickle.load(open('model.pkl', 'rb'))
```

## 6. FAANG-Level Interview Preparation

### System Design & "What If" Questions
* **The Scalability Problem:** "If you have 100 million rows of housing data, will a standard `LinearRegression().fit()` work?"
    * **Answer:** No, it will likely cause a Memory Error. Use **Online Learning** with `SGDRegressor`. It processes data in small batches, making it memory-efficient for large-scale systems.
* **Multicollinearity Challenge:** "What if two features, like `AveRooms` and `AveBedrms`, are 95% correlated?"
    * **Answer:** This is **Multicollinearity**. It makes the coefficients unstable and difficult to interpret. In a real system, you would drop one of the redundant features or use **Principal Component Analysis (PCA)**.
* **Underfitting Diagnosis:** "Your model achieved only 60% accuracy. How do you improve it?"
    * **Answer:** The data might have non-linear relationships. You could try **Polynomial Regression**, feature interaction terms, or more complex algorithms like Random Forests.
