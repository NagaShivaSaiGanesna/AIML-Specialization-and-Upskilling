## 1. The Multi-Class Problem

Binary logistic regression draws a single decision boundary to separate **two** classes. But what if the output has more than two categories?

**Examples:**
- Handwritten digit recognition: classes $\{0, 1, 2, \ldots, 9\}$ — 10 classes.
- Customer tier prediction: Bronze, Silver, Gold — 3 classes.
- Sentiment analysis: Negative, Neutral, Positive — 3 classes.

Standard binary logistic regression cannot handle this directly. We need a strategy to extend it to $K > 2$ classes. The most common approach is **One-vs-Rest (OvR)**, also called **One-vs-All (OvA)**.

---

## 2. One-vs-Rest: Core Idea

The key insight of OvR is to **decompose** a $K$-class problem into $K$ independent binary classification problems.

For each class $k \in \{1, 2, \ldots, K\}$:
- Label class $k$ as the **positive class** (1).
- Label **all other classes combined** as the **negative class** (0).
- Train a dedicated logistic regression model $M_k$ on this binary problem.

Think of it this way: instead of asking *"which of the $K$ classes does this belong to?"*, each model $M_k$ asks *"does this belong to class $k$, or not?"*

For $K = 3$ classes:

| Model | Positive Class | Negative Class |
|---|---|---|
| $M_1$ | Class 1 | Class 2 + Class 3 |
| $M_2$ | Class 2 | Class 1 + Class 3 |
| $M_3$ | Class 3 | Class 1 + Class 2 |

Each model learns a separate **linear decision boundary** in the feature space that isolates its assigned class from the rest.

---

## 3. One-Hot Encoding the Output

Before training, the multi-class target column must be transformed so each binary sub-model has a valid $\{0, 1\}$ target. This is done via **one-hot encoding**.

A categorical label is converted into a binary vector of length $K$, where exactly one position is 1 (the true class) and all others are 0:

| Original Label | One-Hot Vector |
|---|---|
| Class 1 | $[1, 0, 0]$ |
| Class 2 | $[0, 1, 0]$ |
| Class 3 | $[0, 0, 1]$ |

Each **column** of this one-hot matrix serves as the binary target $y$ for the corresponding sub-model — column 1 for $M_1$, column 2 for $M_2$, column 3 for $M_3$.

---

## 4. Training: One Binary Classifier Per Class

Each model $M_k$ is a standard logistic regression trained independently on the **full dataset** using its respective one-hot column as the target.

### 4.1 Model Hypotheses

For $K = 3$ classes with input features $\mathbf{x} = [f_1, f_2, f_3]$:

$$h_{\boldsymbol{\theta}^{(1)}}(\mathbf{x}) = \sigma\!\left(\boldsymbol{\theta}^{(1)T} \mathbf{x}\right) = P(y = \text{Class 1} \mid \mathbf{x})$$

$$h_{\boldsymbol{\theta}^{(2)}}(\mathbf{x}) = \sigma\!\left(\boldsymbol{\theta}^{(2)T} \mathbf{x}\right) = P(y = \text{Class 2} \mid \mathbf{x})$$

$$h_{\boldsymbol{\theta}^{(3)}}(\mathbf{x}) = \sigma\!\left(\boldsymbol{\theta}^{(3)T} \mathbf{x}\right) = P(y = \text{Class 3} \mid \mathbf{x})$$

Each model learns its own **separate parameter vector** $\boldsymbol{\theta}^{(k)}$ by minimizing the standard binary log-loss:

$$J(\boldsymbol{\theta}^{(k)}) = -\frac{1}{m} \sum_{i=1}^{m} \left[ y_k^{(i)} \log\!\left(h_{\boldsymbol{\theta}^{(k)}}(x^{(i)})\right) + (1 - y_k^{(i)}) \log\!\left(1 - h_{\boldsymbol{\theta}^{(k)}}(x^{(i)})\right) \right]$$

### 4.2 Total Parameters

For $K$ classes and $n$ input features (plus bias), OvR trains $K$ separate parameter vectors:

$$\text{Total parameters} = K \times (n + 1)$$

---

## 5. Prediction: Combining All Models

Once all $K$ models are trained, predicting the class label for a new test point $\mathbf{x}^*$ is straightforward.

### 5.1 Prediction Rule

Pass $\mathbf{x}^*$ through each of the $K$ models. Each outputs a confidence score (probability). Select the class whose model is **most confident**:

$$\hat{y} = \underset{k \in \{1, \ldots, K\}}{\arg\max} \; h_{\boldsymbol{\theta}^{(k)}}(\mathbf{x}^*)$$

### 5.2 Worked Example

| Model | Trained For | Output Score |
|---|---|---|
| $M_1$ | Class 1 | $p_1 = 0.25$ |
| $M_2$ | Class 2 | $p_2 = 0.20$ |
| $M_3$ | Class 3 | $p_3 = 0.55$ |

Since $p_3 = 0.55$ is the highest, model $M_3$ wins. $M_3$ was trained to identify **Class 3**, so:

$$\hat{y} = \text{Class 3}$$

### 5.3 Important Caveat: Scores Are Not True Probabilities

In this example, $0.25 + 0.20 + 0.55 = 1.0$ — but this is coincidental. In general, OvR scores **do not sum to 1** because each model was trained independently. You might get $p_1 = 0.8,\; p_2 = 0.7,\; p_3 = 0.3$, which sums to 1.8.

If calibrated probabilities are required, use **Softmax Regression** (multinomial logistic regression), which models all $K$ classes jointly and guarantees a valid probability distribution:

$$P(y = k \mid \mathbf{x}) = \frac{e^{\boldsymbol{\theta}^{(k)T} \mathbf{x}}}{\displaystyle\sum_{j=1}^{K} e^{\boldsymbol{\theta}^{(j)T} \mathbf{x}}}$$

## 6. OvR vs. One-vs-One (OvO)

**One-vs-One (OvO)** is an alternative decomposition strategy. Instead of separating one class from all others, OvO trains a classifier for **every pair of classes**.

- Number of models: $\binom{K}{2} = \frac{K(K-1)}{2}$
- Each model trains only on data from two classes, ignoring all others.
- Prediction: majority vote across all pairwise classifiers.

| Property | One-vs-Rest (OvR) | One-vs-One (OvO) |
|---|---|---|
| Number of models | $K$ | $\frac{K(K-1)}{2}$ |
| Training data per model | Full dataset | Subset (~$\frac{2m}{K}$ examples) |
| Training speed | Faster | Slower |
| Class imbalance risk | Higher (1 vs. $K-1$) | Lower (balanced pairs) |
| Prediction | $\arg\max$ of $K$ scores | Majority vote |
| Best when | $K$ is large | $K$ is small |

## 7. Concept Summary Table

| Concept | Description |
|---|---|
| **One-vs-Rest (OvR)** | Train $K$ binary classifiers; each isolates one class from the rest |
| **One-hot encoding** | Converts a $K$-class label into a binary vector of length $K$ |
| **Sub-model $M_k$** | Standard logistic regression with a binary target for class $k$ |
| **Prediction rule** | $\hat{y} = \arg\max_k \; h_{\boldsymbol{\theta}^{(k)}}(\mathbf{x})$ |
| **Softmax Regression** | Jointly models all $K$ classes; outputs proper calibrated probabilities |
| **One-vs-One (OvO)** | $\binom{K}{2}$ pairwise binary classifiers; predict by majority vote |

## 8. Limitations, Assumptions & Pitfalls

### Limitations
- **OvR scores are not calibrated probabilities.** The $K$ sub-model outputs do not sum to 1. Never treat them as true probabilities without post-hoc calibration (Platt scaling or isotonic regression). Use softmax regression when probabilities matter.
- **Severe class imbalance in each sub-model.** With large $K$, model $M_k$ sees 1 positive class vs. $K-1$ combined negatives. This can cause the model to always predict "not class $k$." Apply `class_weight='balanced'` or resampling per sub-model.
- **Scales poorly for very large $K$.** Training 10,000 separate models (e.g., fine-grained product classification) is computationally heavy. Softmax or hierarchical classification handles large $K$ much better.
- **Linear boundaries only.** OvR with logistic regression assumes each class is linearly separable from the rest. For complex, non-linear boundaries, use kernel SVMs, gradient boosting, or neural networks.

### Assumptions
- Classes are **mutually exclusive** — each data point belongs to exactly one class. If a sample can belong to multiple classes simultaneously, this is a **multi-label** problem requiring a different approach.
- Features should be **standardized** before training since logistic regression is sensitive to feature scale.

### Pitfalls
- **Confusing multi-class with multi-label.** Multi-class = exactly one label per example. Multi-label = multiple labels possible per example. OvR solves multi-class, not multi-label.
- **Reporting OvR scores as probabilities.** Since scores can exceed 1 in total, presenting them as probabilities to stakeholders is misleading.
- **Assuming OvO is always better.** For large $K$, OvO's $\binom{K}{2}$ models become computationally impractical. OvR is the right default at scale.

## 9. FAANG-Level Q&A

---

**Q1.** *What if two or more sub-models output the exact same maximum probability for a new test point? How should ties be broken?*

Perfect numerical ties are extremely rare in practice, but they indicate the test point lies near multiple decision boundaries simultaneously — a genuinely ambiguous example. The standard default (used in scikit-learn) is to pick the class with the smallest index, which is deterministic but arbitrary. A better strategy in production is to flag this as a **low-confidence prediction** and route it to a human reviewer or a secondary model rather than forcing an incorrect guess. Switching to **softmax regression** eliminates the problem entirely, since the shared denominator in the softmax function ensures one class always has a strictly higher probability than the others.

---

**Q2.** *What if one class is extremely rare — say, only 0.1% of the dataset? How does OvR behave?*

Model $M_k$ for the rare class faces a 1:999 imbalance — the log-loss is minimized by always predicting "not class $k$," so the model collapses and the rare class becomes nearly invisible at prediction time. The fix is to apply **cost-sensitive learning** by setting `class_weight='balanced'`, which scales the loss contribution of each class inversely to its frequency:

$$w_k = \frac{m}{2 \cdot m_k}$$

This forces the model to treat one rare-class error as equivalent to many majority-class errors, preventing collapse. Oversampling (SMOTE) and threshold tuning per sub-model are complementary strategies.

---

**Q3.** *What if we skip one-hot encoding and just pass the raw integer labels (0, 1, 2) as targets to a multi-class logistic regression?*

Passing raw integers implies **ordinal structure** — that Class 2 is "between" Class 1 and Class 3, and that the distance from Class 1 to Class 2 equals the distance from Class 2 to Class 3. For nominal categories like animal species or product types, this is mathematically wrong and will bias the learned decision boundaries. The model will be penalized differently depending on whether it confuses Class 1 with Class 2 vs. Class 1 with Class 3, even though both are equally wrong. One-hot encoding (or equivalently, softmax with categorical cross-entropy) treats all class confusions symmetrically, as they should be.

---

**Q4.** *You are building a real-time product categorization pipeline for an e-commerce platform with 500 million listings across 10,000 categories. How would you design this system?*

With $K = 10{,}000$, training 10,000 OvR models is computationally prohibitive and each sub-model would face extreme 1-vs-9,999 imbalance. Instead, exploit the natural **category hierarchy** (e.g., Electronics → Computers → Laptops) and use a two-stage architecture: (1) a text/image embedding model (fine-tuned transformer) encodes each listing into a dense vector, and (2) a **hierarchical softmax classifier** predicts top-level category first (~50 classes), then sub-category within the predicted branch (~200 classes each). For cold-start or ambiguous listings, use **approximate nearest neighbor search** (FAISS) to find the $k$ most similar already-categorized products and take a weighted majority vote. This reduces any single softmax head to a manageable number of classes, keeps inference under 20ms, and allows sub-trees to be retrained independently when new categories are added.
