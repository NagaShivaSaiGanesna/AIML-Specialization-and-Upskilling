# RandomizedSearchCV — Hyperparameter Tuning

## Why RandomizedSearchCV exists

GridSearchCV tries every single combination of hyperparameters. If you have 3 parameters with 5 values each, that's $5^3 = 125$ combinations, each trained $k$ times. This gets expensive fast.

**RandomizedSearchCV solves this by randomly sampling** a fixed number of combinations instead of trying all of them. You control exactly how many combinations to try via the `n_iter` parameter.

$$\text{GridSearchCV fits} = \prod_{i=1}^{p} |V_i| \times k \quad \text{vs} \quad \text{RandomizedSearchCV fits} = n\_iter \times k$$

Where $|V_i|$ is the number of values for parameter $i$ and $k$ is the number of CV folds. With a large grid, the difference is enormous.

---

## GridSearchCV vs RandomizedSearchCV — at a glance

| Feature | GridSearchCV | RandomizedSearchCV |
|---|---|---|
| Strategy | Tries every combination | Randomly samples combinations |
| Controlled by | Size of param grid | `n_iter` parameter |
| Time cost | High on large grids | Low and predictable |
| Guaranteed to find best? | Yes, within the grid | No, but often close enough |
| Best used when | Grid is small | Grid is large or continuous |

## Implementation

```python
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import RandomizedSearchCV

# Same param grid as GridSearchCV
params = {
    'penalty':  ['l1', 'l2', 'elasticnet'],
    'C':        [100, 10, 1.0, 0.1, 0.01],
    'solver':   ['newton-cg', 'lbfgs', 'liblinear', 'sag', 'saga']
}

model = LogisticRegression()

random_cv = RandomizedSearchCV(
    estimator=model,
    param_distributions=params,  # note: param_distributions, not param_grid
    n_iter=20,                   # try only 20 random combos instead of all 75
    cv=5,
    scoring='accuracy',
    n_jobs=-1,
    random_state=42              # for reproducibility
)

random_cv.fit(X_train, y_train)

print(random_cv.best_params_)   # e.g. {'solver': 'saga', 'penalty': 'l2', 'C': 100}
print(random_cv.best_score_)    # e.g. 0.9128

y_pred = random_cv.predict(X_test)
```

> One key difference to notice: the parameter is called `param_distributions` in RandomizedSearchCV, not `param_grid`. Using the wrong name will raise an error.

## Important pitfall — incompatible combinations

The warning about *"L1 ratio must be between 0 and 1"* that appears during training happens because some solver–penalty combinations are invalid (e.g. `elasticnet` requires an `l1_ratio` to be explicitly set, and not all solvers support all penalties). RandomizedSearchCV will randomly land on these invalid combinations and skip them with a warning. To avoid noisy warnings, either restrict your grid to valid combinations or handle them explicitly.

---

## When to use which

Use **GridSearchCV** when your parameter grid is small (under ~100 combinations total) and you want the guaranteed best result within your defined grid.

Use **RandomizedSearchCV** when your grid is large, when parameters are continuous ranges, or when training time is a constraint. In practice, RandomizedSearchCV with `n_iter=50` often finds a result very close to GridSearchCV's best — in a fraction of the time.

The recommended workflow is: **start with RandomizedSearchCV** to find a promising region of the hyperparameter space, then **narrow down with GridSearchCV** around the best values found.
