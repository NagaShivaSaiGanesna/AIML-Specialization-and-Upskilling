# SVM: Math Intuition, Cost Function, and Hard vs Soft Margin

---

## 1. The Equation of the Decision Boundary

In 2D, a straight line can be written as:

$$w_1 x_1 + w_2 x_2 + b = 0$$

In vector form, this is simply:

$$\mathbf{w}^\top \mathbf{x} + b = 0$$

This is the equation of the **best-fit line** (or hyperplane in higher dimensions) that SVM tries to find.

### What is w?

$\mathbf{w}$ is the **weight vector** and it is always **perpendicular (90°) to the decision boundary**. This geometric fact is critical — it is what allows us to calculate distances cleanly.

> **Intuition:** Imagine the decision boundary as a wall. The vector $\mathbf{w}$ is an arrow sticking straight out of that wall, pointing toward the positive class side.

---

## 2. Signed Distance: Why Points Get + or − Values

When you plug any point $\mathbf{x}$ into $\mathbf{w}^\top \mathbf{x} + b$, you get a signed number. The sign tells you which side of the boundary the point is on:

| Location of point | Angle between w and x | Value of $\mathbf{w}^\top \mathbf{x} + b$ |
|---|---|---|
| Above the boundary | 0° to 90° | **Positive** |
| On the boundary | 90° | Zero |
| Below the boundary | 90° to 180° | **Negative** |

This signed distance is the foundation of everything else in SVM. Every subsequent formula builds on this fact.

---

## 3. The Two Marginal Planes

Along with the central decision boundary, SVM defines two **marginal planes** — one on each side — that pass through the nearest points of each class (the support vectors):

$$\mathbf{w}^\top \mathbf{x} + b = +1 \quad \text{(positive marginal plane)}$$

$$\mathbf{w}^\top \mathbf{x} + b = -1 \quad \text{(negative marginal plane)}$$

The value $\pm 1$ is a conventional choice used in most research papers (it could be $\pm k$ for any constant $k$, but $\pm 1$ simplifies the math).

---

## 4. Deriving the Margin Width

Let $\mathbf{x}_1$ be a point on the positive marginal plane and $\mathbf{x}_2$ be a point on the negative marginal plane. Then:

$$\mathbf{w}^\top \mathbf{x}_1 + b = +1$$

$$\mathbf{w}^\top \mathbf{x}_2 + b = -1$$

Subtracting the second from the first:

$$\mathbf{w}^\top (\mathbf{x}_1 - \mathbf{x}_2) = 2$$

To get the actual perpendicular distance (not just the raw dot product), we project onto the unit vector of $\mathbf{w}$ by dividing both sides by $\|\mathbf{w}\|$:

$$\text{Margin width} = \frac{2}{\|\mathbf{w}\|}$$

> **Why the unit vector?** The unit vector normalises the direction of $\mathbf{w}$ so that the distance is a true geometric distance, not just a scaled score. All points get normalised to values between 0 and 1 in this unit-vector space.

---

## 5. The SVM Objective: Maximise the Margin

The entire goal of SVM is to maximise this margin:

$$\text{Maximise} \quad \frac{2}{\|\mathbf{w}\|}$$

Maximising $\frac{2}{\|\mathbf{w}\|}$ is equivalent to **minimising** $\|\mathbf{w}\|$, which is equivalent to minimising $\frac{1}{2}\|\mathbf{w}\|^2$ (the square makes the math cleaner):

$$\min_{\mathbf{w}, b} \quad \frac{1}{2}\|\mathbf{w}\|^2$$

---

## 6. The Constraint: Only Correctly Classified Points Count

The optimisation above must be done subject to a constraint — we only want the margin to be maximised for correctly classified points. The constraint is:

$$y_i \left( \mathbf{w}^\top \mathbf{x}_i + b \right) \geq 1 \quad \text{for all } i$$

**Why does multiplying by $y_i$ work?**

Consider two cases:

- If $y_i = +1$ (positive class): we need $\mathbf{w}^\top \mathbf{x}_i + b \geq +1$. Multiplying: $(+1) \times (\geq 1) = \geq 1$. ✓
- If $y_i = -1$ (negative class): we need $\mathbf{w}^\top \mathbf{x}_i + b \leq -1$. Multiplying: $(-1) \times (\leq -1) = \geq 1$. ✓

Both cases collapse into a single elegant constraint: $y_i(\mathbf{w}^\top \mathbf{x}_i + b) \geq 1$.

---

## 7. Hard Margin vs Soft Margin

### 7.1 Hard Margin SVM

**Hard margin** applies when the two classes are **perfectly linearly separable** — there is no overlap and every point is correctly classified with zero error.

$$\min_{\mathbf{w}, b} \quad \frac{1}{2}\|\mathbf{w}\|^2 \quad \text{subject to} \quad y_i(\mathbf{w}^\top \mathbf{x}_i + b) \geq 1 \;\; \forall i$$

**Problem:** In the real world, data is almost never perfectly separable. There will always be noise, outliers, and overlapping points. Hard margin SVM breaks completely in this situation.

### 7.2 Soft Margin SVM

**Soft margin** is the practical, real-world version of SVM. It allows some points to violate the margin constraint — but penalises each violation.

Two components are added to the cost function:

**Component 1 — Hyperparameter $C$:** Controls *how many* misclassified points are tolerated. A large $C$ tolerates fewer violations; a small $C$ tolerates more.

**Component 2 — Slack variable $\xi_i$ (eta):** Measures *how far* each violated point is from its correct marginal plane. It is the distance of the incorrect data point from the marginal plane it should be on.

The soft margin cost function becomes:

$$\min_{\mathbf{w}, b} \quad \frac{1}{2}\|\mathbf{w}\|^2 + C \sum_{i=1}^{n} \xi_i$$

where $\xi_i = \max(0,\ 1 - y_i(\mathbf{w}^\top \mathbf{x}_i + b))$ — this is the **hinge loss**.

> **Analogy:** $C$ is like a budget. It says "I can accept up to this much total error." $\xi_i$ is the cost of each individual error — how far outside the margin the violated point has strayed.

---

## 8. The Complete SVM Cost Function

$$\boxed{ \min_{\mathbf{w}, b} \quad \underbrace{\frac{1}{2}\|\mathbf{w}\|^2}_{\text{maximise margin}} + \underbrace{C \sum_{i=1}^{n} \max\!\left(0,\ 1 - y_i(\mathbf{w}^\top \mathbf{x}_i + b)\right)}_{\text{hinge loss (penalise violations)}} }$$

| Term | Name | Purpose |
|---|---|---|
| $\frac{1}{2}\|\mathbf{w}\|^2$ | Regulariser | Keeps weights small → margin wide |
| $C$ | Regularisation parameter | Controls tolerance for violations |
| $\max(0, 1 - y_i(\mathbf{w}^\top \mathbf{x}_i + b))$ | Hinge loss | Penalises each margin violation |

---

## 9. Hard Margin vs Soft Margin — Side by Side

| Property | Hard Margin | Soft Margin |
|---|---|---|
| Data requirement | Perfectly linearly separable | Allows overlap and noise |
| Errors allowed | Zero | Some (controlled by $C$) |
| Cost function | $\frac{1}{2}\|\mathbf{w}\|^2$ only | $\frac{1}{2}\|\mathbf{w}\|^2 + C\sum\xi_i$ |
| Real-world use | Almost never | Almost always |
| Risk | Fails if any overlap exists | Can overfit if $C$ is too large |

---

## 10. Intuition for the Hyperparameter C

$$C \uparrow \text{ (large)} \;\Rightarrow\; \text{fewer violations allowed} \;\Rightarrow\; \text{narrow margin} \;\Rightarrow\; \text{risk of overfitting}$$

$$C \downarrow \text{ (small)} \;\Rightarrow\; \text{more violations allowed} \;\Rightarrow\; \text{wide margin} \;\Rightarrow\; \text{risk of underfitting}$$

Choosing the right $C$ is done through cross-validation in practice.

---

## 11. Limitations, Assumptions & Pitfalls

**Assumptions:** The hard margin formulation assumes perfect linear separability, which is unrealistic in practice. The soft margin assumes that a linear boundary (or a kernel-transformed linear boundary) is appropriate for the data.

**Limitations:** The SVM cost function has no closed-form solution — it must be solved iteratively using quadratic programming or SGD. Choosing $C$ incorrectly leads to either an over-sensitive boundary (large $C$) or a boundary that ignores too many points (small $C$).

**Pitfalls:** A very common mistake is forgetting that $y_i \in \{-1, +1\}$ in SVM, not $\{0, 1\}$ as in logistic regression. Using the wrong labels completely breaks the constraint $y_i(\mathbf{w}^\top \mathbf{x}_i + b) \geq 1$. Also, not normalising features before training SVM will distort the distance calculations since $\|\mathbf{w}\|$ is sensitive to feature scale.

## 12. FAANG-Level Q&A

**Q1. What if the margin constraint $y_i(\mathbf{w}^\top \mathbf{x}_i + b) \geq 1$ is satisfied but the model still generalises poorly?**

This can happen when $C$ is set too high, causing the margin to become very narrow even though no training violations exist. The model has memorised the training data — a hard-margin-like behaviour on soft-margin data. The fix is to reduce $C$ to widen the margin, accepting a few training violations in exchange for better generalisation. Cross-validation on a held-out set should guide this choice. Regularisation exists precisely to prevent this: a wide margin, not just correct classification, is the true goal of SVM.

---

**Q2. What if two support vectors from opposite classes are equidistant from the decision boundary, but there are 50 other points much further away — do those 50 points affect the boundary at all?**

No — once points are correctly classified with margin $\geq 1$, their hinge loss is exactly zero and their gradient contribution to the weight update is zero. Only the support vectors (points on or inside the margin) determine the position of the boundary. This is one of SVM's elegant properties: the solution is sparse, defined entirely by a small subset of training points. Removing all non-support-vector points from the training set and retraining would produce the identical decision boundary.

---

**Q3. What if $C$ is set to infinity in the soft margin formulation?**

Setting $C \to \infty$ means any margin violation carries an infinite penalty, which forces the optimiser to allow zero violations. This mathematically collapses soft margin SVM into hard margin SVM. If the data is not linearly separable, the optimisation problem becomes infeasible (no solution exists). In practice, $C = \infty$ should never be used on real data — it is only theoretically equivalent to hard margin and only valid when the classes are perfectly separable.

---

**Q4. How would you scale SVM-based classification to a system with 100 million training points and a requirement for daily retraining?**

Standard SVM solves a quadratic programming problem with $O(n^2)$ to $O(n^3)$ time complexity, making it completely infeasible at 100 million points. The practical architecture involves several layers: first, use a **linear SVM trained with SGD** (hinge loss + L2 regularisation), which achieves $O(n)$ training time and is the only tractable option at this scale. Second, distribute training across a cluster using **data parallelism** — each worker computes gradients on a shard, and a parameter server aggregates them (similar to how Vowpal Wabbit or Spark MLlib operate). Third, for non-linear boundaries, replace the kernel with **Random Fourier Features** (Rahimi & Recht, 2007), which approximate the RBF kernel in a fixed-dimensional feature space, allowing a linear SVM to be applied on top. Fourth, implement **incremental learning** — rather than retraining from scratch daily, warm-start from yesterday's weights and run a single pass over new data. The margin constraint's sparsity property (only support vectors matter) can also be exploited to cache and reuse support vectors across retraining cycles, significantly reducing compute per day.
