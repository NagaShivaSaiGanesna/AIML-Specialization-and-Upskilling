# Multiple Linear Regression

Real-world phenomena are rarely governed by a single factor. While Simple Linear Regression provides a foundation, **Multiple Linear Regression (MLR)** allows us to model complex systems where a single outcome is influenced by a diverse set of independent variables.

---

## 1. Defining the Core Difference

The transition from Simple to Multiple Linear Regression is a shift from modeling a single cause-and-effect relationship to modeling a multi-factorial system.

| Feature | Simple Linear Regression | Multiple Linear Regression |
| --- | --- | --- |
| **Independent Variables ($x$)** | Exactly one (e.g., Weight) | Two or more (e.g., Rooms, Size, Location) |
| **Dependent Variable ($y$)** | Exactly one (e.g., Height) | Exactly one (e.g., House Price) |
| **Geometric Shape** | A 2D **Best Fit Line** | A 3D **Plane** or $n$-Dimensional **Hyperplane** |
| **Complexity** | Easy to visualize (x-y plot) | Impossible to visualize beyond 3 dimensions |

---

## 2. The Mathematical Equation

In Multiple Linear Regression, we extend the linear equation to accommodate $n$ number of features. Each feature is assigned its own weight, signifying its relative importance to the prediction.

### The Hypothesis Function:

$$h_\theta(x) = \theta_0 + \theta_1x_1 + \theta_2x_2 + \theta_3x_3 + \dots + \theta_nx_n$$

### Component Breakdown:

* **$\theta_0$ (The Intercept):** The baseline value of $y$ when every single independent variable ($x_1, x_2, \dots, x_n$) is zero.
* **$x_1, x_2, \dots, x_n$ (Input Features):** The different dimensions of your data (e.g., $x_1$ = sq ft, $x_2$ = age of house).
* **$\theta_1, \theta_2, \dots, \theta_n$ (The Coefficients/Weights):** These represent the **partial effect** of each feature. Specifically, $\theta_j$ tells us how much the predicted $y$ changes for a one-unit increase in $x_j$, **holding all other variables constant**.

---

## 3. High-Dimensional Gradient Descent

In MLR, the "cost bowl" we visualized in simple regression becomes a high-dimensional surface. We are no longer just adjusting a slope and an intercept; we are adjusting a coordinate in $n+1$ dimensional space to find the **Global Minima**.

### The Optimization Goal:

We must simultaneously update every parameter $\theta_j$ using the Gradient Descent update rule:

$$\theta_j := \theta_j - \alpha \frac{\partial}{\partial \theta_j} J(\theta_0, \theta_1, \dots, \theta_n)$$

### The Process:

1. **Multi-Dimensional Steepest Descent:** The algorithm calculates the partial derivative for every $\theta$ simultaneously.
2. **Directional Vector:** These partial derivatives form a **gradient vector**, which points in the direction of the steepest increase in error.
3. **The Step:** The model takes a step in the exact opposite direction of that vector to reduce the cost $J$ most efficiently.

---

## 4. Assumptions, Pitfalls, and Limitations

1. **The Linearity Assumption:** MLR assumes that the relationship between the features and the target is additive and linear. If the relationship is multiplicative or curved, MLR will produce a poor fit.
2. **Multicollinearity:** This occurs when independent variables are highly correlated with each other (e.g., predicting house price using "Square Meters" and "Square Feet"). This makes the coefficients ($\theta$) unstable and difficult to interpret.
3. **Overfitting:** As you add more features ($x_n$), the model may start "memorizing" the noise in your specific training set rather than learning the general trend. A model with 100 features for 100 data points will have zero error but will fail on new data.
4. **Feature Scaling Requirement:** Because we are dealing with multiple variables of different units (e.g., $1-5$ bedrooms vs. $500-5000$ sq ft), Gradient Descent will be incredibly slow unless all features are scaled to a similar range.

## 5. FAANG-Level System Design & "What If" Questions

* **System Design (Feature Selection):** Imagine you are building a pricing engine for Uber. You have 1,000 potential features (weather, traffic, historical price, user battery level, etc.). How do you programmatically decide which features to keep in your Multiple Linear Regression model to avoid **overfitting** while maintaining **predictive power**?
* **The "What If" of Categorical Data:** MLR equations require numbers. What if one of your features is "Neighborhood Name" (e.g., Hyderabad, Seattle, London)? How do you mathematically represent a string in the equation $h_\theta(x) = \theta_0 + \theta_1x_1$? (Hint: Research **One-Hot Encoding**).
* **The "What If" of Missing Data:** In a real-world dataset of 1 million houses, $20\%$ of them are missing the "Year Built" value ($x_3$). Does the Gradient Descent calculation fail? How would you handle these null values before passing them into the MLR equation?
* **The "What If" of Non-Linearity:** What if the relationship between "Experience" and "Salary" is actually exponential? How can you use a **Linear** Regression model to fit that **Non-Linear** relationship? (Hint: Think about transforming the input $x$ before it hits the model).



To solve these challenges, we have to look beyond the basic equation and think about **Data Pipelines** and **Model Robustness**. These are the exact problems you’ll face when deploying a model at a company like Google or Meta.

---

## 1. System Design: Automated Feature Selection

With 1,000 features, a human can't manually pick which ones are "good." We use automated strategies:

* **Stepwise Regression:** We add or remove features one by one and calculate a score (like **Adjusted $R^2$** or **AIC**) to see if the feature actually improves the model or just adds noise.
* **Regularization ($L1$ / Lasso):** This is the "FAANG favorite." In the cost function, we add a penalty for having too many coefficients. **Lasso Regression** has a special property where it forces the coefficients of useless features to exactly **zero**, effectively performing automatic feature selection for you.
* **Feature Importance via Correlation Matrix:** Before training, we use a heatmap to identify features that are highly correlated with the target ($y$) but not with each other.

---

## 2. What If: Categorical Data (e.g., Neighborhood Name)

Linear Regression only understands numbers. You cannot multiply "Hyderabad" by a coefficient $\theta_1$.

* **The Solution: One-Hot Encoding:** We create "dummy" binary columns for each category.
* If you have three cities (Hyd, BLR, DEL), you create three columns.
* A house in Hyderabad would have $x_1=1, x_2=0, x_3=0$.


* **The Pitfall: The Dummy Variable Trap:** You must always drop one of the encoded columns (use $n-1$ columns). If you know a house is NOT in BLR and NOT in DEL, it *must* be in Hyd. Including all three creates perfect **Multicollinearity**, which breaks the Gradient Descent stability.

---

## 3. What If: Missing Data ($20\%$ Null Values)

Gradient Descent cannot calculate a derivative if $x_i$ is `NaN` (Not a Number).

* **Strategy A: Deletion:** If you have millions of rows, you might just delete the $20\%$. But in a FAANG context, data is expensive; deleting $20\%$ might throw away valuable patterns.
* **Strategy B: Imputation:** We "fill in" the gaps.
* **Simple:** Use the **Mean** or **Median** of the column.
* **Advanced (MICE):** Use *another* Linear Regression model to predict the missing "Year Built" values based on the other features like "Price" and "Location."


* **Strategy C: Indicator Variable:** Create a new column "Year_Built_Missing" (0 or 1). This tells the model that the absence of data might itself be a signal.

---

## 4. What If: Non-Linear Relationships

If the relationship between Experience ($x$) and Salary ($y$) is a curve, a straight line will have a massive error.

* **Polynomial Transformation:** We create a new feature by squaring the existing one ($x^2$).
* Even though $x^2$ is non-linear, the **parameters** $(\theta)$ are still linear in the equation: $y = \theta_0 + \theta_1x + \theta_2x^2$.
* This allows a "Linear" model to fit a curved line.


* **Log Transformation:** If the data grows exponentially, we take the $log(x)$ or $log(y)$. This "squashes" the large values and often turns an exponential curve into a straight line that MLR can easily handle.
